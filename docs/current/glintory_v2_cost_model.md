# Glintory v2 コスト試算

ステータス: Phase 0 ドラフト(2026-08-16 調査値に基づく)

方針([実行計画 §7](glintory_v2_execution_plan.md)): AI 費用を除くインフラ費を無料枠内に収める。以下でそれが成立することを、実測前の設計値で確認する。

## 1. 前提値(2026-08-16 調査)

| 項目 | 値 | 確認状況 |
|---|---|---|
| D1 無料枠 | 読取 500万行/日、書込 10万行/日、ストレージ 5GB(1DB最大500MB)、毎日 00:00 UTC リセット | 一次確認済 |
| D1 REST API | Cloudflare API 共通制限 1,200リクエスト/5分 | 一次確認済 |
| R2 無料枠 | 10GB-月、Class A 100万/月、Class B 1,000万/月、エグレス無料、ライフサイクルルール利用可 | 一次確認済 |
| Pages 無料枠 | 500ビルド/月、カスタムドメイン可(Loka 側で使用) | 一次確認済 |
| GitHub Actions | パブリックリポジトリは実行分数無料、ジョブ最大6時間。毎時0分は遅延しやすい | 一次〜準一次 |
| Gemini(Flash 級) | 入力 $0.50 / 出力 $3.00 per 1M tokens、Batch で 50% 割引 | 準一次(※) |
| Gemini(Flash-Lite 級) | 入力 $0.10〜0.25 / 出力 $0.40〜 per 1M tokens | 準一次(※) |

(※)Gemini の単価は Vertex AI 公式ページの Global 価格で確認したもので、Developer API 公式ページ(`ai.google.dev/gemini-api/docs/pricing`)と無料枠(rate-limits)は調査環境から到達不可のため未直接確認。**Phase 0 の残タスクとしてユーザーが AI Studio / 公式ページで確定させる。** 本試算は保守的に「無料枠なし・Flash 級・Batch 未使用」を基準ケースとする。

## 2. 運用規模の想定(初期6源)

| 変数 | 想定値 | 根拠 |
|---|---|---|
| 新規 raw_items | 120件/日 | 官公庁・自治体5源 ≈ 20件/日 + PR TIMES(キーワード事前フィルタ後)≈ 100件/日 |
| 抽出対象クラスタ | 80件/日 | 重複排除・topic フィルタ後 |
| 抽出1件の入力 | 3,500 tokens | 正規化本文 ~3,000 + プロンプト ~500 |
| 抽出1件の出力 | 500 tokens | facts 数件の構造化出力 |
| 元HTML(gzip) | 100KB/件 | 平均的な記事ページ |
| D1 行サイズ | raw_item ~5KB(body_text 込み)、fact ~1KB | |

## 3. インフラ費(結論: 無料枠内、余裕大)

| リソース | 消費見込み | 無料枠比 |
|---|---|---|
| D1 書込 | ~2,000行/日(items + facts + candidates + 更新) | 2% |
| D1 読取 | ~50,000行/日(パイプライン処理 + Retention スキャン) | 1% |
| D1 ストレージ | 定常 ~700MB…ではなく **90日TTLで頭打ち**: 120件×5KB×90日 ≈ 54MB + facts等 ≈ 70MB | 1DB上限500MBの 14% |
| R2 ストレージ | 120件×100KB×90日 ≈ 1.1GB(TTLで頭打ち) | 11% |
| R2 Class A | ~4,000/月(put + lifecycle) | 0.4% |
| Actions | 1実行 10〜20分 × 1日1回 | パブリックリポジトリのため無料 |
| API リクエスト | 1実行あたり D1 数十リクエスト(バッチ書込前提) | 1,200/5分に対し余裕 |

**TTL 設計そのものが容量の上限を規定する**(90日で頭打ち)ため、収集量が3倍になってもストレージは無料枠内に収まる。最初に当たる天井は D1 の 1DB 500MB(収集量 ~7倍で到達)であり、Summary の無料枠消費率レポート(仕様書 §8、80%警告)で監視する。

## 4. AI 費(Gemini)

基準ケース(Flash 級、同期、無料枠なし):

```text
入力: 80件/日 × 3,500 tokens × $0.50/1M = $0.14/日
出力: 80件/日 ×   500 tokens × $3.00/1M = $0.12/日
→ 約 $0.26/日 ≈ $8/月
```

| ケース | 月額目安 |
|---|---|
| 基準(Flash 級・同期) | ~$8 |
| Batch API 利用(50%割引、リアルタイム性不要のため適合) | ~$4 |
| Flash-Lite 級で十分な場合 | ~$1.5〜3 |
| 収集量3倍 + 品質評価パス追加 | ~$25〜30 |

抽出は鮮度要求が緩い(日次バッチ)ため、**Phase 2 で Batch API を第一候補として実装**する。モデルは Flash-Lite 級から始めて出典スパン検証の破棄率で品質を判定し、破棄率が高ければ Flash 級へ上げる(検証が決定論的なので、モデル選定をデータで決められる)。

## 5. 1記事あたり原価(Glintory 供給分)

1記事が平均 5 facts を使い、verified facts の 30% が記事に使われると仮定:

```text
1 fact の抽出原価 ≈ $8/月 ÷ (80件/日 × 30日 × 2 facts/件) ≈ $0.0017
1記事の Glintory 供給原価 ≈ 5 facts ÷ 採用率30% × $0.0017 ≈ $0.03
```

Loka 側の生成費(執筆・翻訳・品質評価)はこれに加算される(Loka 計画側で試算)。Glintory 側は**1記事あたり数セント**であり、Issue の経済性原則(記事数増加に対してコストが急増しない)を満たす。実測値は runs.counters のトークン記録から月次で算出する(成功条件「現金原価を把握できる」の実体)。

## 6. 運用上の注意(調査で判明した制約)

- **Actions cron は毎時0分を避ける**(高負荷帯で遅延・ドロップあり)。`17 21 * * *` のような分をずらした指定にする。
- **パブリックリポジトリは60日間活動がないとスケジュールが自動停止**する。日次実行 + provenance コミットがある限り実質問題ないが、長期停止からの再開手順に注記する。
- D1 無料枠は日次リセットのため、バックフィル等の一時的大量処理は日を跨いで分割する。
- Gemini 無料枠は当てにしない(設計は従量前提)。無料枠が使えれば上振れボーナスとして扱う。
