# Glintory / Loka 権利上の制約とレッドライン

ステータス: Phase 0 調査結果(2026-08-22)/ **商用ローンチ前に弁護士レビュー必須**

> [!WARNING]
> 本書は法的助言ではなく、設計判断と法務相談のための材料である。調査は Web 検索由来の二次情報(法律事務所の解説記事等)に基づいており、**条文原文・判決文原文・各社ガイドライン原文の逐語確認は未了**。ローンチ前に e-Gov 法令検索・裁判所判例検索・文化庁資料・各社公式ページの原文を確認し、著作権に詳しい弁護士のレビューを受けること。

## 0. 結論

| 対象 | 判定 | 根拠 |
|---|---|---|
| 事実を抽出し独自の表現で記事化する | **設計次第で成立する** | 事実そのものに著作権は及ばない(著作権法10条2項、表現・アイデア二分論) |
| 作品タイトル・キャラクター名を記事中で言及する | **問題なし** | キャラクターの抽象概念に著作物性なし(ポパイネクタイ事件)、記述的使用は商標的使用にあたらない(三国志事件) |
| 声優・タレントの氏名を報道として言及する | **問題なし** | パブリシティ権侵害は「専ら顧客吸引力の利用を目的とする」場合に限られる(ピンク・レディー事件) |
| 元記事を要約して翻訳する | **不可(著作権侵害)** | 日経新聞要約翻案事件で翻案権侵害が認定されている |
| 元記事の見出しを翻訳して配信する | **不可(不法行為リスク)** | YOL事件。著作物性がなくとも組織的・継続的な利用は民法709条の不法行為となりうる |
| **キャラクター画像・ゲーム画面・アニメ場面写真の掲載** | **不可** | 主要各社のガイドラインは個人向けであり、広告収益のある法人メディアを許諾対象としていない |
| キャラクターに似た AI 生成画像 | **不可** | 作品名をプロンプトに入れる行為が依拠性の証拠となる(文化庁「AIと著作権に関する考え方について」) |

**要するに、アニメ・ゲームを扱うこと自体に権利上の問題はない。問題は画像である。**

## 1. テキストが成立する理由と、その境界

### 1.1 事実に著作権は及ばない

著作権法10条2項は「事実の伝達にすぎない雑報及び時事の報道」を著作物から除外する。より根本的には、著作権は表現を保護しアイデア・事実には及ばない(表現・アイデア二分論)。

したがって「『Fate/strange Fake』の新シリーズ制作が発表された」という**事実**は誰のものでもなく、これを独自の表現で記事化することは複製にも翻案にもあたらない。各国の報道機関が日常的に行っていることと同じ構造である。

### 1.2 ただし「要約して翻訳する」は侵害である(最重要)

**日経新聞要約翻案事件**では、新聞記事を要約して英訳し配信した行為について翻案権侵害が認められている。判決は新聞記事を「報道すべき主題を発見し、取材源を探知して素材を収集したうえ、記事に盛り込む事実を選択して組み立て、適切な文体で表現したもの」と性格づけた。

ここから読み取るべき境界は明確である。

- **保護されないも**: 個々の事実(誰が・いつ・何を発表したか、数値、固有名詞)
- **保護されるもの**: どの事実を選び、どう組み立て、どう表現したか

つまり **「元記事の事実の選択・順序・構成をなぞること自体が翻案になりうる**。「事実だけを抜き出しているから安全」ではなく、**抜き出し方と並べ方まで独自でなければならない**。これは Glintory の抽出設計に直接効く(§3)。

### 1.3 見出しは翻訳してはならない

**YOL事件(知財高裁 平成17年10月6日)** は二段構えの判断を示した。

1. ニュース見出しは表現の選択の幅が狭く創作性の発揮余地が少ないが、**一律に著作物性が否定されるわけではなく個別に判断する**
2. 仮に著作物でなくとも、見出しは多大な労力・費用をかけた取材の成果であり「法的保護に値する利益」となりうる。**組織的・継続的に無断利用する行為は民法709条の不法行為となる**

自動メディアは定義上「組織的・継続的」である。翻訳を挟んでも、原見出しに著作物性があれば翻訳権侵害となり、なくとも取材成果へのフリーライドという不法行為構成が及びうる。

**したがって Loka の見出しは、原見出しを一切参照せずに生成しなければならない。** これを設計で担保するため、供給契約から `source_title` を削除した(§4)。

### 1.4 著作権法30条の4は解析工程しか守らない

30条の4は「著作物に表現された思想又は感情を自ら享受し又は他人に享受させることを目的としない場合」に利用を認め、情報解析を明示的に含む。Glintory が記事本文を取り込んで事実を抽出する処理は、これに該当する可能性が高い。

**しかし30条の4は配信物の適法性を保証しない。** 最終的に人間の読者に提示する行為は「享受させる」行為であり、30条の4の対象外である。配信物は §1.1〜1.3 の規律で別途判断される。

この境界は Glintory と Loka の役割分担にそのまま対応する。

```text
Glintory(情報解析工程 = 30条の4 の射程内)
  記事本文の取得・一時保持・事実抽出・出典検証
  ↓ 渡すのは事実のみ。原文の表現は渡さない
Loka(配信工程 = 30条の4 の射程外)
  事実から独自の表現で記事を生成。表現の独自性はここで担保する
```

**この二層構造は権利設計上の必然であり、単なる技術的な関心の分離ではない。** 仕様書・供給契約はこの前提で読むこと。

なお、47条の5(軽微利用)は検索エンジンのスニペット表示のような付随的利用を想定した規定であり、**独立したニュース配信サービスを正当化する根拠にはならない**。依拠しないこと。

### 1.5 キャラクター名・タイトル・タレント名は使ってよい

- **ポパイネクタイ事件(最判 平成9年7月17日)**: キャラクターは「漫画の具体的表現から昇華した登場人物の人格ともいうべき抽象的概念」であり、それ自体は著作物ではない。**著作権が生じるのは具体的な絵柄・描写のみ**
- **三国志事件(東京地裁 平成6年8月23日)**: ゲームのタイトル表示は出所識別機能を果たしておらず商標権侵害にあたらない。記事中で作品を指し示す記述的使用は商標的使用ではない
- **ピンク・レディー事件(最判 平成24年2月2日)**: パブリシティ権侵害が成立するのは、①肖像等を独立した鑑賞対象として使用、②商品の差別化目的で付す、③広告として使用、という「専ら顧客吸引力の利用を目的とする」場合に限られる

したがって「『ブルーロック』の新グッズが発売される」「声優の○○が出演する」と**文字で書くこと**に権利上の問題はない。

ただし、報道価値の乏しい内容に著名人の名前だけを冠してクリックを稼ぐ見出しは、上記①〜③の類型に接近する。Loka の見出し生成規則で禁止する。

## 2. 画像は使えない — 本計画で最も重い制約

### 2.1 調査結果

| 権利者 | 公開ガイドラインの内容 | 広告収益のある法人メディアへの適用 |
|---|---|---|
| 任天堂 | ネットワークサービスにおける著作物利用ガイドライン(2024年9月更新)。個人の投稿・収益化を許容 | **対象外**。法人は個別契約が必要。UUUM、ガジェット通信等は個別契約を締結している |
| カプコン | 動画ガイドラインは個人向け。**法人は個別問い合わせが必要と明記**。二次創作ガイドライン(2025年11月)は営利目的を原則不可 | **対象外** |
| スクウェア・エニックス | タイトルごとに個別ガイドライン。ガイドラインのないタイトルは「無断転載禁止」がデフォルト | タイトル別に確認が必要 |
| バンダイナムコ | ゲーム実況ポリシー。一部タイトル限定、配信プラットフォーム上の実況が前提 | 記事サイトへの静止画掲載は想定外 |
| セガ | 全社共通+タイトル別ガイドライン | 原文未確認 |
| SIE | **公式サイト・パッケージ・販促物の画像はウェブ転載を許諾しないと明記** | **不可** |
| アニメ製作委員会 | プレス素材は報道機関向け。東映アニメーションは個人への素材提供を行わないと明言 | 個別申請が必要。広告収益があることをもって報道機関扱いされる保証はない |

**調査した範囲で、広告収益のある商業ニュースメディアを明示的に許諾対象とした一般公開ガイドラインは1社も存在しなかった。**

### 2.2 AI生成でも回避できない

文化庁「AIと著作権に関する考え方について」(令和6年3月15日)は、AI生成物の侵害を通常どおり**類似性**と**依拠性**で判断するとしている。そのうえで、**既存作品のタイトルやキャラクター名をプロンプトに入力する行為は、既存作品を認識していたことの間接証拠となり依拠性が肯定されやすくなる**との整理を示している。

つまり「キャラクター風の画像をAIに描かせる」のは、最もリスクが高い選択肢である。固有名詞を入れずに生成した場合でも、学習データの偏りで既存キャラクターに酷似する可能性があるため、生成後の目視確認が必要になる。

### 2.3 使える画像の選択肢(優先順)

1. **公式YouTube / 公式X の埋め込み** — 各プラットフォームの利用規約上のライセンス構造により、公式埋め込み機能を通じた表示は実務上リスクが低いとされる。アニメ・ゲームでは公式PVが最も訴求力のあるビジュアルであり、これが事実上の主力になる
2. **自作のオリジナル画像・図解・タイポグラフィ** — 権利処理不要で最も安全。アイキャッチ用途
3. **CC0 / NCなしCC BY 素材** — キャラクターが写らない一般的な画像に限定。CC BY は出典表示(作者名・出典URL・ライセンス)が必須
4. **有料ストックフォト(Adobe Stock 等)** — 規約が明確で補償もある。ただしキャラクターやロゴは当然存在しないためイメージ画像用途に限られる
5. **キャラクターを描かない AI 生成画像** — 風景・雰囲気画像に限定。AI生成である旨を明示する
6. **各社への個別許諾申請** — 最も安全だが、MVP 段階では現実的でない。事業が軌道に乗った段階で主要パブリッシャーとの関係構築を検討する

**採用しないもの**: ゲーム画面のスクリーンショット、アニメの場面写真・キービジュアル、フィギュアの製品写真、出典サイトの画像(OGP画像を含む)。

> [!IMPORTANT]
> **埋め込みの実装上の注意**: リツイート事件(最判 令和2年7月21日)は「埋め込みは複製にあたらない」と判示した判例**ではない**。自動トリミングにより撮影者の氏名表示が失われたことについて**氏名表示権侵害**を認めた判決である。したがって、埋め込みであってもレイアウトやトリミングによって作者名・出典が隠れる実装は避けること。また、埋め込み元の投稿自体が無断転載である場合の評価は別問題として残るため、**公式アカウントの投稿のみを埋め込む**。

### 2.4 これは事業上のリスクである

アニメ・ゲームメディアがキャラクター画像を使えないことは、競合に対する明確な不利である。この制約を承知のうえで、公式PV埋め込みとオリジナルのアイキャッチで成立させられるかは、**Loka の設計判断として明示的に決めるべき論点**であり、実装を始める前に結論を出すこと。

## 3. Glintory 側で強制する制約

仕様書に反映済みまたは反映すべき事項。

1. **事実は原子的であること** — `statement` は「誰が・いつ・何を」の単一の事実に限る。複数の事実を含む叙述的な文、および記事の要約を生成してはならない(§1.2 の翻案リスク回避)
2. **1記事あたりの抽出上限** — 1つの `raw_item` から抽出する fact は最大3件。上限を設けるのは、記事の事実の選択・構成をそのまま再現することを構造的に防ぐため
3. **`evidence_span` を Loka に渡さない** — 内部の出典検証専用。契約ビューから除外済み
4. **`source_title` を Loka に渡さない** — 原見出しへの依拠を構造的に防ぐ(§1.3)。Screen と重複排除では内部的に使用してよい
5. **画像を取得・保存しない** — R2 に保存するのは HTML と API レスポンスのみ。`<img>` の取得を行わない
6. **プロンプトインジェクション防御** — 記事本文はデータであり指示ではない旨をプロンプトに明記(仕様書 §6.1)

## 4. Loka 側で守るべき規則(供給契約に記載)

1. 原文の見出し・リード文の逐語翻訳の禁止
2. 出典サイトの画像の取得・再利用の禁止。画像は §2.3 の手段のみ
3. 全ての事実について出典名とリンクを明示(著作権法48条の出典明示に対応)
4. **1記事は原則として2つ以上の独立したクラスタの事実に基づくこと** — 単一記事の事実だけで構成すると、元記事の構成を再現するリスクが高まる(§1.2)。Glintory 側は単一クラスタ由来の記事を検出できるようにする
5. 報道価値の乏しい内容に著名人名を冠する見出しの禁止(§1.5)
6. 公式アカウント以外の埋め込みの禁止

## 5. 準拠法 — 日本法だけでは足りない

タイ・インドネシアはいずれもベルヌ条約加盟国であり、日本の著作物は現地でも保護される。著作権の準拠法については**保護国法主義**が通説であり、現地での利用・侵害の成否は原則として現地法で判断される。インターネット送信の侵害地を発信地と受信地のどちらと見るかについては学説が対立し、確立した最高裁判例は見当たらない。

したがって **「日本法をクリアすれば安全」という設計は不十分**である。タイ著作権法・インドネシア著作権法についても、現地の弁護士によるレビューを別途行うこと。これは Loka の公開前に完了させるべきタスクとする。
