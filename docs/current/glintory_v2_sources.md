# Glintory v2 初期情報源リスト

ステータス: 実測ベース(第1ラウンド 2026-08-22 実施)

選定基準は[実行計画 §6](glintory_v2_execution_plan.md)。第一基準は読者価値、第二基準は日10本以上の流量。

## 測定方法

推測を排すため、GitHub Actions 上で候補サイトを実測している(`scripts/discover_feeds.py` / `.github/workflows/discover-feeds.yml`)。各サイトの HTML から `<link rel="alternate">` と RSS 一覧ページのアンカーを辿り、見つからなければ一般的なパスを試し、RSS 2.0 / RDF / Atom をパースして **実際の記事流量と実際の見出し** を出力する。以後、情報源の追加・入れ替えは必ずこの測定を経ること。

## 第1ラウンドの結果(33サイト中17でフィード検出)

### 最重要の発見: 日本の Web は領域によって RSS の生存率が全く違う

| 領域 | フィード検出 | 実態 |
|---|---|---|
| ゲーム・アニメ専門メディア | ほぼ全て検出 | 日40〜65本の高流量。RSS が現役で機能している |
| ネット系トレンドメディア | 検出 | 日15〜70本 |
| 旅行・グルメメディア | 検出するが低流量 | 日1〜3本。記事が「まとめ」型で速報ではない |
| **コンビニ・小売各社** | **全滅** | セブン・ローソン・ファミマとも `<link>` タグ 0 |
| **コスメ・美容** | **全滅** | @cosme・美的とも検出できず |
| **テーマパーク・気象** | **全滅** | TDR・USJ・tenki.jp とも検出できず |
| **ナタリー系(コミック/音楽/映画)** | **検出できず** | 事前調査で日120〜150本と最有力だったが、フィードを発見できなかった |

これは戦略に直結する。**読者価値が最も高く、かつ機械可読な高流量フィードが揃っているのはアニメ・マンガ・ゲームの領域だけ**である。食・コスメ・旅行は、読者価値は高いがフィードで安定取得する手段が乏しい。

## 第2ラウンドの結果(検出できなかった20件を再測定)

RSS 一覧ページのアンカー追跡と媒体別パス推測を追加して再試行し、6件で新たにフィードを検出した。

| 情報源 | 結果 | 判定 |
|---|---|---|
| セブン-イレブン | **検出** `www.sej.co.jp/company/news_release/index.rss`(日0.6、17件) | 条件付き採用(下記) |
| ローソン | 検出したが IR 専用フィード。最新記事が **771日前** で事実上停止、内容も「決算資料」「月次情報」 | 不採用 |
| ウォーカープラス | イベントページからも同じ Web 漫画フィードに到達。イベント専用フィードは存在しない | 不採用 |
| ファミリーマート | 検出できず | 不採用 |
| ナタリー系3 / アニメイトタイムズ / アキバ総研 / ファミ通 / ORICON / モデルプレス / tenki.jp / 東京ディズニーリゾート / USJ / @cosme / 美的 | 検出できず | 不採用 |

**ナタリーは2ラウンドとも検出できなかった**。事前調査では日120〜150本で最有力だったが、RSS を提供していないと判断する。東京ディズニーリゾートはトップページの取得自体が失敗しており、ボット遮断の可能性が高い。

### セブン-イレブンを例外的に採用する理由

流量 日0.6本は第二基準(日10本以上)を満たさない。それでも採用するのは、**コンビニ新商品が読者需要の高いテーマでありながら、他に取得手段が一切ないため**である。第二基準は「記事化候補が枯渇しないこと」を担保するためのものであり、それは主要6源で既に満たされている。したがって本源は「量を稼ぐ源」ではなく「独自テーマを補う源」として扱う。

ただし実際の見出しは「組織変更および人事異動に関するお知らせ」「令和8年熊本地震被害への支援物資お届けのご案内(第4〜6報)」が大半で、有用なのは「セブン‐イレブンに全15品のカレー商品が登場！『カレーフェス』を開催」のような商品発表のみ。`exclude_patterns` に人事・IR・災害支援・組織変更を設定し、実質的に商品発表だけを通す。

## 測定で判明した設計上の重要事実: `published_at` は信用できない

診断の結果、フィードが返す公開日時は媒体によって全く信用できないことが分かった。

- **ITmedia(ねとらぼ)**: 最新記事の `pubDate` が `Mon, 26 May 2025 14:50:00 +0900` を返す。記事内容(一番くじ ケロロ軍曹など)は明らかに現在のものであり、**日付が1年以上ずれている**
- **grape**: 最新記事は3時間前で正常だが、フィード内に常時掲載の古い記事が混在し、流量の推定が成立しない
- **ローソン**: 771日前の記事を新着として返し続けている

このため仕様書 §5.3 を改訂し、**鮮度判定・TTL・優先順位付けは全て `collected_at`(Glintory が初めて観測した時刻)を基準とする**ことにした。`published_at` は参考値として保存するのみで、未来日付または365日以上前の場合は NULL 化する。推測で設計していたら確実に踏んでいた地雷であり、測定した価値がここにある。

## テーマ構成の評価と、それが意味すること

採用6源のテーマ構成は、アニメ・ゲーム・キャラクターIPに偏る。これは妥協ではなく、次の2つが一致した結果である。

1. タイ・インドネシア読者の日本に対する最大の関心はアニメ・マンガ・ゲームである
2. 日本の Web で高流量の機械可読フィードが生き残っているのも、まさにこの領域である

したがって **Loka 1か国目はポップカルチャーを軸に立ち上げる**。食・旅行・コスメは読者価値が高いにもかかわらずフィードが貧弱なため、ロケットニュース24 と PR TIMES で部分的に補い、Loka の成立が確認できた後に取得手段を拡張する。

## 権利の扱い

[実行計画 §6](glintory_v2_execution_plan.md)の設計制約に従う。特に本リストの媒体は全て商業メディアまたは企業発であり、以下を実装で強制する。

- `evidence_span` は内部検証専用。Loka へ渡さない(供給契約で担保済み)
- 見出し・リード文の逐語翻訳を禁止
- **画像を一切取得・再利用しない**
- 出典名とリンクを記事に必ず明示
- robots.txt 尊重、同一ホストへのリクエスト間隔を確保

ITmedia(ねとらぼ)は RSS 利用条件を明文化しており、私的利用は無償、商用転載は要許諾、本文の抜粋転載は禁止としている。事実抽出+独自表現+出典明記という本設計はこれと整合するが、採用時は `license_note` にこの条件を明記する。

## manifest への反映

採用源を `config/sources.json`(仕様書 §4)へ登録する。PR TIMES と GIGAZINE は `include_keywords` を、各源は `exclude_patterns` を設定して Screen で絞る。フィード URL は測定が返した最終 URL を正とする。
