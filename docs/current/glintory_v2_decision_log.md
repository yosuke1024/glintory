## 1. 決定

**Glintory v2 / Loka を一旦保留し、時間を PixWork と Simple Games に寄せる。**

Phase 0(設計)は完了、Phase 1(実装)には着手しない。v1 のコードは削除していないため、リポジトリは着手前の状態のまま。

### 理由

**(1) 法務コストが期待収益を上回る**

インフラと AI のコストは想定どおり安い(無料枠内 + Gemini 月$8程度)。問題は Phase 0 で新たに判明した法務コストで、日本の著作権弁護士による設計レビューに加え、タイ・インドネシアの現地法レビューが必要になる(ベルヌ条約 + 保護国法主義のため日本法だけでは足りない)。3法域分を真面目に行えば数十万〜百万円規模になり得る一方、東南アジア向け広告の単価は低く初年度の期待収益はほぼゼロである。

**(2) Issue 自身の経済性の原則を満たさない**

Issue には「収益より現金コストが大きくなる場合は継続しない」「PixAppsへの送客を理由に単体赤字を正当化しない」と明記されている。外部の基準ではなく、企画自身が定めた継続条件を現スコープは満たさない。

**(3) 需要が未検証**

Phase 0 では供給側(情報源・権利)のみを調査し、需要側を一切検証していない。タイ語・インドネシア語で日本の情報がどれだけ検索されているかが不明なまま、権利と実装の議論を積み上げてしまった。**投資判断の前提が欠けている。**

### 優先順位の観点

Issue の2026年実施順序では、8〜10月中旬は PixWork のローンチと Simple Games の立ち上げ、Gemini モデル移行が優先で、Glintory は10月後半からとされている。保留は元の計画順序に戻すことに等しく、無理のある判断ではない。

### 手戻りから得た教訓

- **選定基準は、それが何を最適化しているかを疑うこと。** 初版の基準(法的安全・機械可読・一次情報・週次以上)は全て満たされたが、読者価値がゼロだった。基準を満たすことと目的を達することは別である。
- **到達できない情報は推測で埋めず、到達できる環境で測ること。** 事前調査でナタリーは「日120〜150本で最有力」とされたが、実測ではフィードが存在しなかった。逆に「記事数が少ない」とされた電ファミニコゲーマーは日44本だった。
- **供給側より需要側を先に確認すること。** 今回はこの順序を誤った。

## 3. 確定した知見(再導出しないこと)

### 3.1 技術・情報源(実測値。詳細は[情報源リスト](glintory_v2_sources.md))

- **日本の Web は領域ごとに RSS の生存率が全く違う。** ゲーム・アニメ専門メディアはほぼ全て健在で日40〜65本の高流量。一方、**コンビニ各社・コスメ・テーマパーク・気象・ナタリー系はフィードを提供していない**(33サイト中17検出、第2ラウンドでも6/20)
- 旅行・グルメメディアはフィードがあっても日1〜3本で流量が足りない
- **`published_at`(フィードの公開日時)は信用できない。** ITmedia は最新記事に1年以上前の `pubDate` を返す。ローソンは771日前の記事を新着として返し続けている。鮮度判定・TTL・優先順位付けは全て `collected_at` 基準にすべき
- ファミ通の RSS は2024年頃に停止済み
- セブン-イレブンは `www.sej.co.jp/company/news_release/index.rss` を持つが日0.6本で、大半が人事異動と災害支援
- ウォーカープラスのメインRSSはイベント情報ではなく Web 漫画エッセイ
- 測定ツール `scripts/discover_feeds.py` は再利用可能。GitHub Actions 上で動かせば実測できる

### 3.2 権利(詳細は[権利文書](glintory_v2_rights.md))

**テキストは成立するが境界が狭い**

- 事実そのものに著作権は及ばない。アニメ・ゲームを扱うこと自体に問題はない(キャラクターの抽象概念に著作物性なし=ポパイネクタイ事件、タイトルの記述的使用は商標的使用でない=三国志事件、報道としての氏名言及はパブリシティ権を侵害しない=ピンク・レディー事件)
- **ただし要約して翻訳する行為は翻案として侵害が認められている**(日経新聞要約翻案事件)。保護されないのは個々の事実だが、どの事実を選びどう組み立てたかは保護される
- **見出しは翻訳してはならない。** 著作物性がなくとも組織的・継続的な利用は不法行為となりうる(YOL事件)
- **著作権法30条の4は解析工程しか守らない。** 配信物の適法性は別途判断される。47条の5(軽微利用)は独立したニュース配信の根拠にならない

**画像は成立しない**

- 任天堂・カプコン・スクウェア・エニックス・バンダイナムコ・セガ・SIE のいずれも、**広告収益のある商業メディアを許諾対象とした公開ガイドラインを持たない**。多くは個人向けで、任天堂は法人に個別契約を求めている。SIE は販促画像のウェブ転載を許諾しないと明記
- キャラクターに似た AI 生成画像も不可。作品名をプロンプトに入れる行為が依拠性の証拠になる(文化庁の考え方)
- 使えるのは公式YouTube/X の埋め込み、オリジナル画像、CC0/CC BY、有料ストック、キャラクターを描かない AI 画像のみ
- リツイート事件(最判 令和2年)は「埋め込みは複製にあたらない」とした判例では**ない**。氏名表示権に関する判決であり射程を広げないこと

**掲示板まとめは商業メディアより危険**

- 保守速報事件で「まとめただけ」の抗弁が排斥され、**選別・見出し付け・並べ替えという編集行為が独立した不法行為**とされた(大阪地裁 平成29年11月16日 200万円、大阪高裁 平成30年6月28日 控訴棄却、最高裁 平成30年12月11日 確定)。Glintory の機能の本体がまさに選別と編集であるため、正面から衝突する
- 京アニ事件関連で、虚偽情報を掲載したまとめサイトに約360万円・185万円・約400万円の賠償命令
- **著作権は事実だけ抽出すれば回避できるが、名誉毀損は回避できない**
- 5ch は2014年以降 転載禁止が原則で許可制。掲示板の書き込みにも著作物性を認めた裁判例あり(東京地裁 平成14年4月15日)
- プロバイダ責任制限法の「媒介者」免責は、記事化している時点で期待できない

**プレスリリース配信プラットフォーム**

- 「報じてもらうための情報だから二次利用が自由」という仮説は**誤り**。法的な特則は存在しない
- 主要5社はいずれも「**報道目的の範囲**」かつ「**登録メディア会員であること**」という二重の制約構造。無条件のフリーライセンスではない
- ただしメディア登録という形であれば、1回の手続きで数千社の発表が使えるようになる
- 共同通信PRワイヤーが最も明確(登録メディア会員は報道活動に必要な範囲で複製・転載・編集が可能と規定)。PR TIMES は日1,000〜1,300件と配信量が最大で企業別・キーワード別RSSが実在するが、2024年9月に登録条件を厳格化している
- **画像の包括的な「報道利用可」規定はどこにもない**

### 3.3 戦略上の核心

**今回の権利問題はすべて「他人の書いた記事を情報源にする」という1つの選択から派生していた。** 情報のギャップを埋めるという企画の目的自体を否定する材料は出ていない。壊れたのは手段である。

Glintory の設計は「事実と表現を分離し、事実だけを構造化して持つ」ものであり、**事実には著作権が及ばないため、設計の方向自体は正しかった**。問題は Loka 側で、分離した事実を再び記事に戻し、元の情報源と同じ土俵で競わせようとしていた点にある。記事にした瞬間に表現の問題が復活する。

したがって、再開する場合の有力な代替は **事実を記事に戻さない方向**(放送・発売スケジュール、イベント開催情報、商品発売情報などを現地語で引ける構造化データとして提供する)。記事生成という最もリスクの高い工程を丸ごと削れ、Glintory の `facts` + `entities` + 日付 + TTL という構造がそのままプロダクトになる。ただしメディアよりユーティリティに近く、1ページあたりの広告収益は記事型より低くなる可能性が高い。

## 4. 未解決の問い

再開時に答えるべきもの。**上から順に、コストが低く判断への影響が大きい順**。

1. **需要はあるか(最重要・未着手)** — タイ語・インドネシア語で日本の情報がどれだけ検索されているか。キーワードボリュームの実データが必要(Google キーワードプランナー、Ahrefs 等)。ここが薄ければ以降の問いは全て不要になる
2. **記事型か、事実データ型か** — §3.3 の選択。法務コストと収益性のトレードオフ
3. **メディア登録は認められるか** — PR TIMES / 共同通信PRワイヤーに自動生成メディアがメディア会員として登録できるか。規約を読んでも分からない可能性が高く、申請するのが最も確実
4. **プレスキット素材は機械判別できるか** — PR TIMES のプレスキット指定素材が API/フィードから判別できれば、1件ごとの法務確認なしに使える画像を自動選別できる。画像問題の唯一の突破口
5. **Loka の画像方針** — 公式PV埋め込みとオリジナルのアイキャッチだけでメディアとして成立するか

## 6. 再開する場合の順序

1. **需要検証から始める。** §4 の問い1。ここが薄ければ再開しない判断ができる
2. 需要があれば、記事型か事実データ型かを決める(§3.3)
3. 方向が決まってから、その方向に必要な範囲だけ法務確認を行う。**記事型なら3法域のレビューが必要だが、事実データ型ならスポット相談で足りる可能性がある**
4. 法務の見通しが立ってから Phase 1 に着手する

**やってはいけない順序**: 基盤を作ってから使える情報源がないと判明すること。今回 Phase 0 で止まったのはこれを避けられたということであり、設計プロセスとしては機能している。
